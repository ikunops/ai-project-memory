## 0. 现状（一句话）

`scripts/sculpt.py` 目前是 ~186 行单文件，CLI 路由 + 正则解析 + 文件 IO + 错误处理全挤在一起。
基本流程能跑通，但在 **并发写入、半路崩溃、含代码块的复杂文档** 三类场景下会 **丢数据 / 误解析**。

---

## 1. 必须改的三个硬伤（P0，按依赖顺序串行）

> 依赖链：**P0-1 → P0-2 → P0-3**。没有 P0-1 打底，P0-2/3 是在不稳定基础上叠加，收益减半。

### P0-1　提案身份：用「稳定 ID」取代「行号索引」

- **问题**：`approve` / `reject` 用「第 N 条」行号定位。一旦文件被外部编辑、行号漂移，操作就会打错对象。
- **改法**：每条提案用内容派生 ID —— `P-<sha256(类别:规则)[:8]>`（见下方 `compute_id` 思路）。
  - `approve P-xxxx` / `reject P-xxxx` 精确引用，不再依赖行号；
  - 旧格式（无显式 ID）也能按内容即时算出临时 ID，无需先升级文件格式。
- **验收**：
  1. 相同 `(类别, 规则)` 永远得到相同 ID；
  2. `approve P-xxxx` 精准命中，与行号无关；
  3. 外部插入一行后，原有 `P-xxxx` 仍指向同一条。

### P0-2　文件写入：做成「事务」

- **问题**：`f.write_text(...)` 直接覆盖。两进程并发、或半路崩溃，会 **丢更新** 或留下 **半截文件**。
- **改法**（零三方依赖）：
  1. 写前取**文件锁**（跨平台：`os.open(O_CREAT|O_EXCL)` 锁文件，带过期锁回收）；
  2. 先写**临时文件** → `fsync` → `os.replace` **原子替换**原地；
  3. **写前 hash 校验（Fail-Closed）**：若磁盘内容已被外部改动（hash 不匹配），**拒绝覆盖**，原文件不动。
- **验收**：
  1. 写入中途杀进程 → 原文件完整、无残留 `.tmp`；
  2. 两进程先后操作同一文件 → 结果都不丢；
  3. 外部改过再操作 → 报错退出、原文件 hash 不变。

### P0-3　解析器：改成「状态机」

- **问题**：`re.match(r'^##\s*(\[[^\]]+\])')` 逐行判区块，**完全不认识代码块**。
  文档里若示例代码含 `## [待确认]`，会被误判成真区块 / 真提案。
- **改法**：用 `OUTSIDE_CODE / INSIDE_CODE` 两态机。只有代码块**之外**的 `## [xxx]` 才算区块边界；
  代码块内的 `- [类别]：...` 也不算提案。
- **验收**：
  1. 代码块内的 `## [待确认]` **不**新增区块；
  2. 代码块内的 `- [类别]：...` **不**被算作提案。

## 2. 建议执行顺序（黄金垂直切片）

1. **先钉死「身份 → 状态 → 持久化」三不变量**，只在一类对象（提案 `Proposal`）的单条链上验证；
   **不碰** Host / Plugin / Audit / RBAC 等其它模块。
2. 按 **P0-1 → P0-2 → P0-3** 串行落地（见依赖链）。
3. 每落一项，对照上方「验收」逐条自测通过，再进下一项。
