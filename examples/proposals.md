# 提案示例库

展示"决策上下文"格式的正确与错误写法，供雕刻师比对参考。

## 正确示例（含决策上下文）

```
[技术选型]：计算密集任务优先考虑 Rust
  （证据：用户明确要求低内存占用，且已有 Cargo.toml 配置；
    使用条件：仅当任务满足"低内存"前提时适用）
```

```
[运维规范]：生产库变更必须走审批
  （证据：2026-08 曾因直接 DELETE 造成数据事故；
    使用条件：仅针对 production 环境）
```

```
[反例]：关于"高并发网络服务"，用户明确拒绝 Python 方案
  （证据：3 次交互中均被否定，2026-08-10 最后确认；
    建议：优先考虑 Go/Rust）
```

## 错误示例（会被自检拒绝）

```
[规则]：用 Python 解决
```
✗ 无证据、无使用条件、无范围 → 会形成"路径依赖"

```
[规则]：gunicorn 超时就加 worker
```
✗ 只记录了"止痛药"，没记录"为什么反复超时"和"何时该换方案"

## 反过拟合自检清单

写入前逐条确认：

- [ ] 这条规则是否包含"为什么"（证据/背景）？
- [ ] 是否包含"使用条件"（什么时候适用）？
- [ ] 是否存在被否决过的替代方案？（若有，补 [反例] 条目）
- [ ] 是否含敏感信息（密钥/密码/内网地址）？→ 不含才可写入
- [ ] 是否能在 3 行内表达完？→ 不能则拆分或精简
- [ ] 是"项目特有的决策"还是"通用知识"？→ 通用知识不写，让模型自身能力处理
